# 具有舆论属性或社会动员能力的互联网信息服务安全评估规定

中文 · [English](social-mobilisation-security-assessment-provisions.md)

> 国家互联网信息办公室和公安部 **2018-11-15 发布**，**自 2018-11-30 施行**，共十七条，**没有令号**。网信办自己的定性是三句：属于**政策性文件**、**不属于行政许可事项**、**不设立行政处罚措施**。本库收它的理由很具体：**"具有舆论属性或社会动员能力"这个触发条件，全行业只有本规定第二条划出了范围**——算法推荐规定第二十四条的备案、深度合成规定第十九与第二十条、生成式 AI 办法第十七条、拟人化办法第二十二条全都往这里转致，而那几部的官方解读一处都没给判定标准。

## 一句话是什么

凡是能影响舆论、能发动公众的服务——论坛、博客、微博客、聊天室、通讯群组、公众账号、短视频、网络直播、信息分享、小程序——**上线前自己做了安全评估、把评估报告经全国互联网安全管理服务平台交给属地地市级以上网信部门和公安机关**，接受书面审查与现场检查；**拒不评估的，国家不罚你，而是在平台上向公众提示你的服务存在安全风险**。

## 本库最需要的一节：第二条划出的范围

- **第二条** 本规定所称具有舆论属性或社会动员能力的互联网信息服务，包括下列情形：
  - （一）开办**论坛、博客、微博客、聊天室、通讯群组、公众账号、短视频、网络直播、信息分享、小程序**等信息服务**或者附设相应功能**；
  - （二）开办**提供公众舆论表达渠道**或者**具有发动社会公众从事特定活动能力**的其他互联网信息服务。
- **第三条** 五种须自行开展安全评估的情形，且提供者**对评估结果负责**：①服务上线或增设相关功能；②使用新技术新应用，使功能属性、技术实现方式、基础资源配置等发生重大变更，导致舆论属性或者社会动员能力发生重大变化；③**用户规模显著增加**导致上述重大变化；④**发生违法有害信息传播扩散**，表明已有安全措施难以有效防控网络安全风险；⑤**地市级以上网信部门或者公安机关书面通知**需要进行安全评估的其他情形。
- 一个值得记下的文本细节：**标题用"或"，正文第三条里"舆论属性或者社会动员能力"又用"或者"**，两种写法混用。这不影响适用，但引用时要照所引文本的写法抄。

## 关键条款

| 条款 | 要求 |
|---|---|
| 第一条 | 依据：《中华人民共和国网络安全法》《互联网信息服务管理办法》《计算机信息网络国际联网安全保护管理办法》。 |
| **第二条** | 定义适用范围（见上节）——十类服务＋两项兜底。 |
| **第三条** | 五种自行评估触发情形；提供者对评估结果负责。 |
| 第四条 | 安全评估**可以自行实施，也可以委托第三方安全评估机构实施**。 |
| 第五条 | 评估要覆盖信息服务和新技术新应用的**合法性**、落实法律法规规章和**标准**规定安全措施的**有效性**、防控安全风险的有效性，并**重点评估八项**：①确定与所提供服务相适应的**安全管理负责人、信息审核人员或者建立安全管理机构**；②**用户真实身份核验以及注册信息留存**措施；③对用户账号、操作时间、操作类型、**网络源地址和目标地址、网络源端口、客户端硬件特征**等日志信息以及用户发布信息记录的**留存**措施；④对账号和群组名称、昵称、简介、备注、标识及发布、转发、评论、群组功能中**违法有害信息的防范处置**和记录保存；⑤**个人信息保护**以及防范违法有害信息传播扩散、**社会动员功能失控**风险的技术措施；⑥**投诉、举报制度**及公布渠道与及时受理处理；⑦为**网信部门**履职提供技术、数据支持和协助的机制；⑧为**公安机关、国家安全机关**维护国家安全和查处违法犯罪提供技术、数据支持和协助的机制。 |
| 第六条 | 发现安全隐患应及时**整改直至消除**；符合法律法规规章和标准的应形成**安全评估报告**，含①功能、服务范围、软硬件设施、部署位置等基本情况和**相关证照获取情况**；②安全管理制度和技术措施落实情况及风险防控效果；③**评估结论**；④其他应说明情况。 |
| **第七条** | **交到哪里、什么时候交**：报告经**全国互联网安全管理服务平台**提交**所在地地市级以上网信部门和公安机关**。属第三条第一项、第二项情形的，须在**上线或增设功能前**提交；属第三、四、五项情形的，**自相关情形发生之日起 30 个工作日内**提交。 |
| 第八条 | 地市级以上网信部门和公安机关依职责**书面审查**；内容、项目缺失或**评估方法明显不当**的，**责令限期重新评估**；内容不清的可以**责令补充说明**。 |
| 第九条 | 依书面审查情况认为必要的可开展**现场检查**；两部门**原则上联合实施，不得干扰正常业务活动**。 |
| 第十条 | 对存在较大安全风险、可能影响国家安全、社会秩序和公共利益的，**省级以上**网信部门和公安机关应组织**专家评审**，必要时会同属地部门现场检查。 |
| 第十一条、十二条 | 现场检查依法律法规规章进行；两部门建立**监测管理制度**，发现未按本规定开展评估的，**通知其开展评估**。 |
| **第十三条** | **拒不评估的后果**：应通过全国互联网安全管理服务平台**向公众提示该服务存在安全风险**，并依职责实施监督检查，发现违法行为依法处理。 |
| 第十四条 | **网信部门统筹协调**，公安机关的安全评估工作情况**定期通报网信部门**。 |
| 第十五条 | 履职中知悉的国家秘密、商业秘密和个人信息**严格保密**，不得泄露、出售或者非法向他人提供。 |
| 第十六条 | 互联网新闻信息服务新技术新应用的安全评估，依照《互联网新闻信息服务新技术新应用安全评估管理规定》执行。 |
| 第十七条 | 自 **2018 年 11 月 30 日**起施行。 |

## 它不是什么——以及对对照的意义

网信办的表述是三条：**属于政策性文件**、**不属于行政许可事项**、**不设立行政处罚措施**；对未开展评估就上线的服务，管理部门**通过平台发布安全风险提示信息**（[网信办转载·网络传播杂志](https://www.cac.gov.cn/2019-03/20/c_1124259405.htm)）。所以中国的这一环是**报告＋曝光，而非审批**：国家不批准你的服务，而是让你把本已在《网络安全法》下应尽的义务写下来、送给两个部门，拒不写就公开提示风险。 — **A**（条文）／**B**（这段定性来自官方对该文件的表述，不是文件本身）

两点后果：**第一**，AI 产品被要求做的"安全评估"就是这部 2018 年的义务，它按**服务类型**触发、比三部 AI 规章都早，不是 AI 专门评估；**第二**，这部规定不设罚则，所以 AI 规则的执行牙齿仍在库里已经写好的位置——《网络安全法》第六章第 61–77 条，以及新规章自己的操作性制裁（责令暂停、限制功能、下架）。

## 与既有法律的关系

- **三处转致最终落到这里**：[深度合成规定](deep-synthesis-provisions-zh.md)第二十条（开发上线新产品、新应用、新功能"按照国家有关规定"开展安全评估）、[生成式 AI 办法](generative-ai-services-measures-zh.md)第十七条、[拟人化办法](ai-anthropomorphic-interaction-measures-zh.md)第二十二条；同一措辞还驱动[算法推荐规定](algorithmic-recommendation-provisions.md)第二十四条的**备案**。范围都由本规定第二条定。
- **依据（第一条）**：[网络安全法](cybersecurity-law.md)（真实身份、日志留存、事件处置——即第五条要核验的义务）加两部行政法规。
- **第十六条另立门户**：互联网新闻信息服务的新技术新应用评估走自己的规定。
- **对照欧盟**：欧盟没有对应的层次：没有哪部欧盟法会因为一个服务**发动公众的能力**就要求它上线前自评并向两个部门报告。AI Act 的符合性评估按**系统的风险分类**触发、对 GPAI 模型则落到技术文档（见 [`../eu/ai-act-zh.md`](../eu/ai-act-zh.md)）；结构上最接近的是 GDPR 第 35 条的 DPIA——但那是**内部留存、不上交**，触发条件是高影响处理而非受众动员力。本节比较为本库判读。 — **C**
